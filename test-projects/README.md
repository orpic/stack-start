# Test projects

Real, minimal apps generated by each framework's own generator. They are the main test bed for stackstart: the conformance cases in [`../conformance/cases/projects/`](../conformance/cases/projects/) start them, edit their files, request them over HTTP and stop them, the way a developer or an agent would.

Only sources and lockfiles are committed. Dependencies, build output and databases (`deps/`, `_build/`, `node_modules/`, `.venv/`, `.data/`, `storage/*.sqlite3`) are created by each project's `setup` profile and ignored by git.

| [`stackstart.yaml`](stackstart.yaml) (composite) | Postgres → Phoenix + Node API + React Router + a tunnel whose URL is captured and passed on | postgres 5545, phoenix 4110, api 3110, web 5310 | `setup-all`, `fullstack` (cloudflared), `fullstack-ngrok`, `fullstack-offline`, `tunnel-fails`, `bad-migration` |

Ports never overlap, so every project can run at the same time.

## Running one by hand

```bash
cd test-projects/phoenix_app
stackstart up setup     # once: install dependencies (oneshots; exits when done)
stackstart up dev       # the app and everything it needs
stackstart down         # from any other terminal
```

The composite profiles live in `test-projects/stackstart.yaml`, so they are visible from every project below it:

```bash
cd test-projects
stackstart up setup-all
stackstart up fullstack-offline
```

## Toolchains

| Project | Needs |
| --- | --- |
| phoenix_app | Elixir 1.17+ / OTP 26+, Postgres (`initdb`, `postgres`) |
| django_app, fastapi_app | Python 3.13 (`.tool-versions` pins it for asdf) |
| node_api, react_router_app | Node 22+ and npm |
| rails_app | Ruby 3.4 (`.tool-versions`, `.ruby-version`) and Bundler |
| composite | all of the above; `cloudflared` for `fullstack`, an ngrok authtoken for `fullstack-ngrok` |

Cases skip with the reason when a toolchain is missing.

## Rules for changing them

- Generate with the framework's own tool; keep changes minimal and commented.
- Keep the ports in the table above.
- `dev` must work offline once `setup` has run (except the tunnel profiles).
- Postgres is always project-local through [`tools/pg-init`](tools/pg-init), never a developer's own database.
- After changing a project, run its cases: `tmp/conformance --bin tmp/stackstart --filter 'projects/<project>/*'`.
